AI エージェントを日常的に使う開発では、**最も効果の大きいレビュー対象はコードそのものから、allow と deny と hooks の設計へ移ります。** 事後に差分を読む作業がなくなるわけではありません。ただし、それより前に効く層が一つ増え、そちらのほうが止められる事故の数が多くなります。

根拠は現場の感覚ではなく、ツール側のドキュメントが引いている線にあります。

> **要点**
> この記事の主張
>
> - 公式ドキュメントは「指示」と「強制」をはっきり分けており、CLAUDE.md は前者に属する
> - 権限ルールとフックは、レビューのチェックリストのうち機械で担保できる項目を実行可能にしたもの
> - ただし権限は「正しさ」をレビューしない。置き換えではなく、前に足す層である

## まとめ

- 公式ドキュメントは「指示」と「強制」を分けており、CLAUDE.md は強制の層ではない
- `permissions.deny`、`ask`、critical path、PreToolUse フックは、レビュー項目を実行可能にしたもの
- 設計対象は許可ルール・フック・実行環境の 3 層。広すぎる allow は auto モードで落とされる
- 権限は正しさをレビューしない。コードレビューの置き換えではなく、その前に足す層である
- 最初に決めるのは、不可逆な操作の deny と、外部に出る操作の ask の 2 つでよい
