CLAUDE.md にテストの規約、API の設計方針、フロントエンドのスタイル規則まで書いていくと、あっという間に 200 行を超えます。公式ドキュメントは「長いほど指示への追従が下がる」と明記しており、関係ない規約まで毎回読ませるのは損です。

結論として、`.claude/rules/` にトピック別の Markdown を置き、必要なものには `paths` フロントマターを付けると、そのパターンに一致するファイルを Claude が扱うときだけルールが読み込まれます。

> **要点**
> この記事で分かること
>
> - `.claude/rules/` の置き方と、`paths` を付けたルールと付けないルールの読み込みタイミング
> - グロブパターンの書き方(拡張子、ディレクトリ、ブレース展開)
> - ユーザー用ルール `~/.claude/rules/` との優先順位と、シンボリックリンクでの共有

## まとめ

- `.claude/rules/` に 1 トピック 1 ファイルで置く。`paths` が無いルールは起動時に読み込まれ、節約にはならない
- `paths` のグロブに一致するファイルを Claude が読んだときだけ読み込まれるのがパス限定ルール
- ブレース展開は 1,000 パターン・4 MiB が上限。`[` はエスケープする
- `~/.claude/rules/` は先に読まれ、プロジェクトのルールが優先される
- 共有はシンボリックリンクで。毎回不要な手順はスキルに切り出す
