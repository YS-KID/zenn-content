**CLAUDE.md と AGENTS.md は設計ドキュメントの復権ではありません。** 設計書と違うのは「毎回読まれる」という 1 点だけで、その代わりに長さの上限と結合の優先順位という制約が付いています。設計書の体裁で書くとかえって効きが落ちる、別の種類の文書です。

この見立ては感想ではなく、両ツールの公式ドキュメントが書いている読み込み規則から出てきます。

> **要点**
> この記事の主張
>
> - 「毎回読まれる」は設計書が持てなかった性質で、ここだけは本当に新しい
> - 読まれることと従われることは別で、公式ドキュメントが保証しないと明言している
> - 長さの上限があるため、設計書の内容をそのまま載せる使い方には向かない

## まとめ

- context files が設計書と違うのは「毎回読まれる」1 点。Codex は「there is no cache to clear manually」と明言している
- 読まれることは従われることではない。CLAUDE.md はユーザーメッセージとして届き、厳密な遵守は保証されない
- 長さの上限がある。Claude Code は 200 行で遵守率が落ち、Codex は 32 KiB で打ち切る
- 矛盾した指示は人間に気づかれず、片方が任意に選ばれる
- 短く書ける決定事項は context files へ、意思決定の背景は設計ドキュメントへ。1 つで足りるという前提だけが消えた
